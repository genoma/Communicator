# Security & performance audit — 2026-08-29

Scope: full dependency audit plus a read-only source-level review of `src/`
(~12.7k lines, 71 files) on branch `chore/security-perf-audit`, branched from
`main` at `3.46.0`. **Not merged into `main`** — review and merge separately.

## Baselines (before any change)

- `npm audit`: 0 vulnerabilities (107 total deps).
- `eslint .` and `knip`: clean.
- `npm test`: 1540 passing.

## Method

- Two independent fresh-context review lanes (security, performance) ran in
  parallel over the same tree; every reported finding was then re-verified in
  the parent against the source before any fix was applied.

## Fixes applied

| # | Severity | Finding | Fix |
|---|----------|---------|-----|
| 1 | Low (security) | `extractMarkdownImageUrls` regex backtracked quadratically on model-controlled text shaped `![x](https://` + long run with no closing `)` (`src/artifacts.js`) | Replaced with a linear one-pass scan; same accepted URL shapes, verified against the existing tests plus malformed-input cases |
| 2 | Low (security) | SSE stream accumulation unbounded (`fullTextParts`, `buffer`, …); a slow-drip or newline-less hostile stream bypasses the idle timeout (`src/sse-parser.js`) | Hard byte cap `MAX_STREAM_BYTES` = 128 MB on raw chunk bytes (option `maxBytes`); exceeding throws a non-retryable `ApiError` and cancels the reader |
| 3 | High (perf) | `partialContext` re-parsed the whole accumulated buffer per partial redraw on boundary-less streams (long list/paragraph) → O(n²) (`src/ui/markdown.js`) | `partialContext` now applies the same 64-line `TAIL_WINDOW` cap as `processBatch` (same guards: fences/tables suppress it; `lines` empty guard for the first partial) |
| 4 | Medium (perf) | `computeGrid` re-wrapped every editor line twice per keystroke (cursor row three times) (`src/editor/layout.js`) | Wrap each line once, reuse segments/starts/drops for the cursor math — identical output, verified by the editor grid + parity suites |
| 5 | Low (perf) | `dataUrlRefCache` unbounded (`src/attachment-store.js`) | Bounded at 512 entries; eviction transparent (content-addressed blobs, later write is an EEXIST no-op) |

## Kept report-only (no change)

- `session-sidecar.js` writes the whole `.index.json` per entry update — save
  happens at exit/commands, not per turn; batching would change durability
  semantics for an O(sessions) cost on large libraries only.
- `renderHistory` re-parses/re-wraps the whole transcript on resize/resume —
  not a per-chunk hot path.
- E2EE debug prompt-log (`--debug --rpg`) stores plaintext messages — local,
  opt-in artifact; same trust level as `history.json`.
- Major dependency versions (latest are @inquirer/core 12, commander 15,
  markdown-it 15): not taken — a major bump is a behavior change, not audit
  work; only in-range updates were applied (@inquirer/prompts 8.7.0,
  markdown-it 14.3.1, eslint 10.9.1).

## Claimed, investigated, disproven

- `wrapSegmentsDetailed` within-line O(n²): false. After a hard cut the
  residual is a single char; after a fold it is at most `limit` wide, so the
  fold-point re-scan is O(limit) per cut with O(n/limit) cuts → O(n) per line.

## Verified clean (independent of this audit)

- API keys: env-only, never persisted/argv/logged, never in error text.
- File modes: config/session/sidecar 0o600, dirs 0o700, atomic writes.
- No eval/Function/vm/shell interpolation; clipboard spawns use fixed args.
- Prototype pollution: `__proto__`/`constructor`/`prototype` filtered on
  preference load/merge; spread-only merges.
- Path traversal: session-id regex, attachment ref shape + resolved-path
  containment, exported-name sanitization.
- SSRF: private/loopback/reserved/NAT64/6to4/Teredo/mapped-IPv4 blocked, DNS
  pinned to validated addresses, per-hop redirect re-validation, https→http
  downgrade rejected, byte caps on downloads.
- Rendering: markdown-it `html: false`; ANSI sanitization at every display
  boundary; hyperlinks http(s)-only and sanitized.
- ReDoS elsewhere: linear/deterministic (extractPartialToken, sanitizeAnsi,
  citation parsing, etc.).
- E2EE: constant-time nonce compare, fail-closed plaintext rejection, key
  on-curve validation, nonce replay guard.
- Retry/timeout discipline: capped attempts, idempotency-gated retries,
  timers cleared in `finally`, no listener leaks.
